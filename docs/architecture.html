Loupe architecture

Loupe is a local-first browser extension that reads social-feed content already rendered in the page, checks each item against user-written rules with a language model, and marks matches inline. This page explains how the code is put together and why.

Chrome MV3 · WXT 0.19 React 19 · TypeScript · Tailwind 4 Reddit + YouTube adapters GroqCloud / TypeSafe providers Next.js 16 website

1. Overview

The repository holds two separate build targets that share a name and a design language but no runtime code:

Product

Browser extension extension/

A dogfood-quality, unpacked Chrome Manifest V3 extension built with WXT. It highlights Reddit posts and YouTube videos that match the user's rules.

Marketing

Website / (repo root)

A Next.js 16 App Router site with waitlist hero variants and a dev-only design-system showcase.

The extension's core loop is passive filtering: as the user scrolls, newly visible feed items are extracted, batched, sent to the selected model provider together with the enabled rules, and matching items receive a colored outline and a badge. Structured collections and on-demand summarization are part of the product vision but are not built yet.

Sources of truth. docs/product-brief.md defines scope, CONTEXT.md defines the domain vocabulary (feed item, adapter, enrichment, rule, match, marker, provider, analysis batch), and docs/adr/ records settled decisions. This page describes how the code implements them.

3. Extension runtime

A Chrome extension runs as several isolated JavaScript contexts that talk only through message passing and shared extension storage. Loupe uses four of them, and their trust levels drive most of the design.

ContextFileResponsibilitiesCan see API key?
Content scriptentrypoints/reddit.content.ts
entrypoints/youtube.content.ts		Builds a FeedController around one site adapter. Observes the DOM, extracts feed items, sends analysis requests, renders markers.No. Receives a sanitized ContentState.
Background workerentrypoints/background.tsRoutes messages, re-checks enabled/consent/provider state before every analysis, calls the provider, tracks per-tab status, broadcasts state changes to open feed tabs.Yes. Reads it from storage per request.
Popupentrypoints/popup/App.tsxRule editor (name, criterion, color, order, enabled), master switch, cloud consent, status line, "Clear markers on this tab".Reads full state from storage but never displays the key.

Why the key stays out of the content script

Content scripts share the page's DOM and run next to untrusted page code. The background worker calls storage.local.setAccessLevel({ accessLevel: "TRUSTED_CONTEXTS" }) so content scripts cannot read storage directly. They get rules and flags through the GET_CONTENT_STATE and STATE_UPDATED messages instead, and the contentState() helper replaces the provider object with a single providerReady boolean.

Manifest

wxt.config.ts requests only storage and tabs, plus host access to www.reddit.com, www.youtube.com, api.groq.com, and api.typesafe.ai. The tabs permission lets the background worker find open feed tabs to broadcast state and identify the active tab for status and marker clearing.

The seam that makes a second platform cheap is the SiteAdapter interface in src/core/types.ts. Adding YouTube required a new adapter and a short content script; FeedController did not change shape.

interface SiteAdapter<T extends FeedItem> {
  isSupportedPage(location: Location | URL): boolean;
  findItemElements(root: ParentNode): HTMLElement[];
  closestItemElement(node: Node): HTMLElement | null;

}

The provider seam is a single function type, (apiKey, items, rules) => Promise<MatchResult[]>, keyed by ProviderKind in src/provider/index.ts. A future in-browser WebLLM provider plugs in at the same place.

5. Analysis pipeline

From a post appearing on screen to a marker being drawn, every step lives in FeedController unless noted.

  1. DiscoverOn start, adapter.findItemElements(document) finds existing items. A MutationObserver on document.body (child list, subtree, href attribute) finds items added by infinite scroll or client-side navigation.
  2. Wait for proximityEach item element is registered with an IntersectionObserver using rootMargin: "600px 0px". Only elements inside or near the viewport are enqueued, so off-screen content costs nothing.
  3. GateEnqueue stops if the page is unsupported, Loupe is paused, consent is missing, the provider is not verified, or no enabled rule has a criterion.
  4. Extract and deduplicateadapter.extractFeedItem(element) produces a plain-data FeedItem. The key fnv1a(item) + ":" + rulesFingerprint is compared with the processed map. A hit re-renders the cached result without a model call.
  5. Debounce and batchNew items join the queue. A 100 ms timer then drains it into batches of at most 5 items with at most 2 batches in flight.
  6. EnrichIf the adapter defines enrichFeedItem (YouTube only), each item is enriched in parallel. Failures return the original item.
  7. AnalyzeThe content script sends ANALYZE_POSTS { items, rules }. The background worker loads state again, rejects the call if paused or not ready, marks the tab analyzing, and dispatches to the selected provider.
  8. ValidateProviders return exactly one MatchResult per item/rule pair. Malformed, missing, duplicate, or unexpected results throw, and the whole batch fails open.
  9. Discard stale responsesIf the rules changed while the request was in flight (fingerprint mismatch) or the page is no longer supported, results are dropped. If an element now shows a different item, its marker is not drawn.
  10. RenderResults are cached per item in tab memory and passed to renderMarker, which skips matches the user dismissed.

6. Message protocol

All cross-context communication uses the ExtensionMessage union in src/core/types.ts, and every reply is an ExtensionResponse: { ok: true, … } or { ok: false, error }. Senders use satisfies ExtensionMessage so a typo in a message type is a compile error.

7. State and storage

Only configuration persists. Everything derived from feed content lives in memory and disappears with the tab, so Loupe builds no browsing history.

DataWhereLifetime
Rules (id, name, criterion, enabled, color, order), master switch, cloud consent, provider kind, API key, verified flagchrome.storage.local under "loupe-state"Persistent until the extension is removed
Per-tab status (setup-required, ready, analyzing, paused, error)Background tabStatuses mapUntil the tab closes or the worker is suspended
Queue, processed fingerprints, match results, dismissalsFeedController fieldsCurrent page lifetime
YouTube video detailsmetadata.ts module cache, up to 500 entries, failures evictedCurrent page lifetime

Two shapes of state

StoredState  = { enabled, cloudConsent, rules, provider: { kind, apiKey, verified } }
ContentState = { enabled, cloudConsent, rules, providerReady }   /* sent to pages */

loadState() in src/core/storage.ts never trusts what is stored: it runs every rule through sanitizeRules() (type checks, length limits, preset colors, max 8 rules), resets an unknown provider kind to the default, and drops consent if the provider kind is invalid. Consent is also reset when the user verifies a different provider, because consent names the service that receives the data.

The popup and options page write storage directly with saveState(). The background worker listens to storage.onChanged and broadcasts the new ContentState, so storage is the single event source for configuration changes.

Element reuse

YouTube recycles one tile element for a different video when the feed changes. The controller handles this with two WeakMaps: seenIds (which item an element last showed) and markedIds (which item its marker belongs to). When a mutation inside a known element changes its item ID, the controller clears the stale marker and re-enqueues the element. Hover previews mutate tiles constantly, so the controller compares IDs first and does nothing when the ID is unchanged.

Adding a platform

  1. Add a FeedItem variant with a site discriminator in src/core/types.ts.
  2. Write src/<site>/adapter.ts implementing SiteAdapter, plus an HTML fixture and tests.
  3. Add a content script entrypoint that creates new FeedController(adapter).
  4. Add the host to host_permissions and FEED_URL_PATTERNS, update the consent text, and record the decision in an ADR.

9. Model providers

The user picks one provider in the options page and supplies their own key. No key is ever bundled.

Default

GroqCloud · openai/gpt-oss-20b

OpenAI-compatible chat completions with response_format: json_object, temperature: 0, and low reasoning effort. One request carries the whole batch: all items and all enabled rules as one JSON prompt. The system prompt states that item fields are untrusted data, never instructions. Returns a one-sentence reason (trimmed to 240 chars) for each match.

Alternative

TypeSafe · jev-latest

A System One classifier. One request per feed item, with each enabled rule asked as one noul question keyed rule_0…rule_n. A probability ≥ 0.5 is a match. No free text comes back, so injected text in a post cannot change the output shape, but markers show a default reason.

Shared behavior (src/provider/shared.ts)

  • ProviderError carries a transient flag. HTTP 429 and 5xx are transient. Everything else, including 401 and quota errors, is permanent.
  • withRetries makes up to 3 attempts with 400 ms then 800 ms backoff, and only for transient errors. TypeSafe retries per item, so one overloaded item does not resend the others.
  • Groq output is strictly validated by parseResults: valid JSON, a results array, correct types, every expected pair present exactly once, nothing extra.
  • testProvider runs one synthetic Reddit item against one synthetic rule. A successful round trip is the definition of "verified".

10. Markers

src/feed/marker.ts draws the only UI Loupe adds to a site.

  • Style isolation. A custom <loupe-marker> element with an open shadow root holds its own stylesheet, so site CSS cannot break it and its CSS cannot leak into the site.
  • Normal flow. The row is prepended or appended inside the item element. No absolute positioning, so it never covers content.
  • Outline, not restyle. The item gets a 2 px outline in the color of the first matching rule in saved order. The original inline outline is stored in a WeakMap and restored on clear.
  • Text, not HTML. Rule names and model reasons are set with textContent and text nodes. Model output is never parsed as HTML.
  • Accessible. Badges are real buttons with aria-expanded and aria-controls, keyboard focus rings, text labels in addition to color, and a dark-mode palette through prefers-color-scheme.
  • Dismissal. "Dismiss" adds postId + ruleId to an in-memory set and re-renders. The next matching rule then supplies the border, or the marker disappears.

11. Caching and re-analysis

Two fingerprints decide whether work is repeated:

  • Item fingerprint: FNV-1a hash of JSON.stringify(item) (src/core/batch.ts). If a post is edited, it is analyzed again.
  • Rules fingerprint: id:criterion of every enabled rule with a criterion, joined in order (analysisFingerprint in src/core/rules.ts). Names and colors are deliberately excluded.

When STATE_UPDATED arrives, applyState compares the rules fingerprint:

Fingerprint changed

A criterion changed, or a rule was enabled, disabled, added, or deleted. Results, queue, and markers are cleared, and every element near the viewport is enqueued again.

Fingerprint unchanged

Only a name, color, order, pause state, or consent changed. Markers re-render from cached results with no model call.

Pausing stops new enqueues but leaves existing markers. "Clear markers on this tab" is a separate, explicit action. A page reload starts with an empty cache and may analyze visible items again. This is the accepted cost of not persisting feed content.

12. Privacy, trust, and failure

What leaves the device

  • To the selected provider: the fields listed in Site adapters plus the enabled rules (id, name, criterion). Nothing else from the page.
  • To YouTube: one cookie-less player request per analyzed video. YouTube already serves this video to the user's page.
  • Never: usernames, votes, comments, view counts, account data, or browsing history.

User control

  • Analysis cannot start until the user verifies a key and accepts a consent notice that names the provider. The master switch is disabled until consent is given.
  • The popup always shows a Cloud indicator while hosted inference is in use.
  • Every match can be explained and dismissed. Markers can be cleared for the tab.

Fail open

Every error path leaves the site unchanged: a missing key, a network failure, quota exhaustion, invalid model output, failed enrichment, or an unsupported layout. Only the per-tab status changes to error, and the popup shows the message. Authentication and quota errors are not retried automatically.

Platform terms still apply. Reading the rendered DOM avoids platform API keys. It is not an exemption from platform terms or privacy law. ADR 0007 records that InnerTube use must be reviewed before any public release.

14. Website (Next.js)

The repo root is a Next.js 16 App Router project with React 19, Tailwind CSS 4, shadcn/ui on Base UI, and next-themes. It shares no runtime code with the extension. ADR 0001 forbids importing next/* or server actions into extension entrypoints.

RouteSourceNotes
/app/page.tsxStarter page, not yet product content.
/hero/1, /hero/2app/hero/[variant]/page.tsxStatically generated (generateStaticParams, dynamicParams = false). Each variant shows a waitlist form backed by the joinWaitlist server action, which validates the email but does not persist it yet.
/design-systemapp/design-system/page.dev.tsxShowcase of tokens and components. next.config.ts adds the dev.tsx page extension only under next dev, so this route returns 404 in production builds.

Design tokens are defined as CSS custom properties in app/globals.css, named by role and split into layers. The extension uses its own small Tailwind stylesheet (extension/assets/tailwind.css) and copies of four UI primitives rather than importing from the website, which keeps the two builds independent.

17. Deferred work

These are product capabilities or decisions that the current architecture leaves room for but does not implement.

  • Local inference. A WebLLM, WebGPU, or WASM provider behind the existing provider function type, which removes the cloud disclosure.
  • Structured collections. Extraction of fields into saved records with source links, which needs retention, export, and deletion rules first.
  • On-demand summaries of threads, comment sections, or profiles.
  • More actions than highlighting: collapse, hide, rank. Deterministic keyword rules that need no model.
  • More platforms (X, LinkedIn, and others) as new adapters, each with its own ADR.
  • Public release work: onboarding, security review, a path off free-tier providers, and a platform-terms review.
